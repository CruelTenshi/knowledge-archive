# 지식 아카이브

감상 아카이브와 같은 디자인을 사용하는 정적 마크다운 위키입니다. 문서 원본은 `db/*.md`에 저장하며 기존 두 아카이브는 수정하지 않습니다.

## 열기

폴더 전체를 정적 HTTP/HTTPS 서버에 올린 뒤 `index.html`로 접속합니다. 브라우저의 JavaScript가 원본 `.md` 파일을 `fetch`로 읽어 표시합니다. 패키지 설치나 빌드 과정은 필요 없습니다.

## 파일 구성

- `index.html`: 메인, 전체 목록, 문서 읽기 화면
- `db.js`: 문서 목록과 메타데이터
- `app.js`: 화면, 검색, 위키 링크, 마크다운 읽기
- `markdown.js`: 수식·각주·위키 링크 처리와 목차 번호
- `core.js`: 날짜 기반 추첨과 정렬·검색 함수
- `document-store.js`: HTTP 문서 읽기와 메모리 캐시
- `style.css`, `cyber.css`: 감상 아카이브의 공통 디자인
- `wiki.css`: 지식 아카이브 전용 레이아웃
- `db/*.md`: 문서 본문
- `db/img/*`: 본문 이미지와 [제작·재생성 기록](db/img/README.md)
- [문서 관리 기록](문서%20관리%20기록.md): 문서 정리와 보강 내역
- `vendor/*`: 로컬 마크다운·HTML 정리 라이브러리와 라이선스
- `tests/core.test.cjs`: 날짜·추첨·목록 무결성 검사

## 문서 추가·수정

1. `db`에 UTF-8 `.md` 파일을 만들고 마크다운 문법으로 작성합니다.
2. `db.js`의 `ARTICLES`에 `{ id, title, file, summary, tags, updatedAt }` 항목을 추가합니다.
3. `file`은 `db` 기준 상대 경로, `id`는 중복 없는 고정 주소입니다.
4. 이미지는 `db/img`에 저장하고 `![설명](img/파일명.png)`로 참조합니다. 하위 폴더의 문서는 `../img/파일명.png`를 사용합니다. `./db/img/파일명.png`도 지원합니다.
5. 파일을 서버에 반영하고 새로고침합니다. 제목·요약·태그·수정일은 `db.js`, 본문은 `.md`에서 수정합니다.

개념 문서 160개가 등록되어 있습니다. 문서를 추가하거나 삭제할 때는 `db`의 파일과 `db.js`의 목록을 함께 관리하세요. 등록된 문서가 없거나 8개보다 적어도 화면이 정상 동작합니다.

문서 통합·개명 전의 ID·제목·파일 경로는 `db.js`의 `REDIRECTS`에서 새 문서와 필요한 절로 연결합니다. 넘겨주기 항목은 전체 목록이나 추첨에 별도 문서로 집계하지 않습니다.

## 링크와 문법

`[[문서 제목]]`, `[[id|표시 이름]]`, `[[id#절 제목|표시 이름]]`, `[표시 이름](other.md)`를 지원합니다. 같은 문서 안에서는 `[이동](<#절 제목>)`을 쓸 수 있습니다. 주소에 공백이 있으면 `<...>`로 감쌉니다. 문서 주소는 `index.html#/doc/id`이므로 정적 호스팅에서도 별도 라우팅 설정이 필요 없습니다. HTML은 DOMPurify로 정리합니다.

## 역링크와 탐색 틀

- 문서 아래 **역링크**를 펼치면 이 문서를 참조하는 다른 문서가 제목순으로 표시됩니다. 위키 링크, 등록된 Markdown 문서 경로, 문서 주소를 인식합니다. 문서마다 한 번만 표시하며 같은 문서와 탐색 틀의 링크는 제외합니다. 처음 열면 전체 본문을 확인하며, 이미 읽은 문서는 검색과 역링크에 함께 사용합니다. 일부 파일을 읽지 못하면 목록에 안내를 표시하고 다시 확인할 수 있습니다.
- 문서에서 빈 줄로 구분한 한 줄에 `{{틀:logic}}`을 쓰면 **비판적 사고와 논리학** 탐색 틀이 나타납니다. `management`는 경영과 기업, `international`은 국제정치의 주요 개념에 사용합니다. 목록에 문서를 추가하거나 그룹을 바꿀 때는 [wiki-templates.js](wiki-templates.js) 한 곳에서 편집합니다. 각 그룹의 `articles`에는 `db.js`에 등록된 문서 ID를 넣습니다.
- 각주는 논거의 출처, 공식의 가정, 용어의 적용 범위처럼 본문을 끊지 않고 확인할 정보에 사용합니다. 핵심 설명은 본문에 둡니다.

선행 개념과 적용 문서가 이어지는 95개 문서에는 상단에 **읽기 흐름** 틀을 붙였습니다. 제목을 누르거나 키보드로 펼치면 번호와 화살표로 권장 읽기 순서를 확인할 수 있고, 현재 문서는 강조됩니다. 같은 단계에 있는 문서는 함께 참고하며 제목을 누르면 해당 문서로 이동합니다. 여러 흐름에 걸치는 문서에는 틀을 여러 개 표시합니다.

읽기 흐름 25개는 회계의 기초·영업·연결·자산·조달·분석, 투자와 가치평가, 시장균형·가격·시장구조, 계약과 정보, 논리·인과 검증, 경영 전략·마케팅·운영·데이터·국제정치에 걸쳐 있습니다. 관련 분야의 문서를 모으는 기존 탐색 틀과 함께 사용할 수 있습니다.

새 흐름은 wiki-templates.js에서 flow를 true로 지정하고 title, description, groups를 작성합니다. groups의 배열 순서가 단계 번호가 되며 각 단계의 articles에는 같은 수준에서 읽을 문서 ID를 넣습니다. 흐름에 포함한 각 문서의 소개 문단 다음에 {{틀:흐름-id}}를 한 줄로 넣습니다. 수정을 마친 뒤 기존 테스트로 문서 ID와 첨부 관계를 확인합니다.

## 추천·검색·정렬

수식은 `$...$`, `$$...$$`, `\(...\)`, `\[...\]`를 지원하며 KaTeX로 표시합니다. 각주는 `본문[^id]`와 `[^id]: 설명`을 사용합니다. 본문의 각주 번호를 누르면 읽던 위치를 유지한 채 팝업에서 내용과 출처를 볼 수 있습니다. 닫기 버튼·바깥 클릭·Esc로 닫으며, 문서 아래 각주로 이동할 수도 있습니다. 키보드로 열기·닫기와 읽던 번호로의 포커스 복귀를 지원합니다. 재참조·여러 문단도 지원합니다. 코드 안의 수식·위키·각주 문법은 그대로 보존합니다. 목차는 모든 제목 단계에 `1`, `1.1`, `1.1.1` 형식의 번호를 표시합니다.

- 오늘의 문서: 한국 날짜(Asia/Seoul)를 시드로 고른 최대 4개. 같은 날짜·같은 목록이면 동일합니다. 배열 순서를 바꿔도 동일하며, 문서를 추가·삭제하면 결과가 바뀔 수 있습니다. 열린 화면은 30초 간격과 탭 복귀 시 날짜를 확인합니다.
- 우연한 발견: 오늘의 문서를 제외한 나머지에서 최대 4개. 새로고침·다시 뽑기마다 선택합니다. 이전 추첨 결과와 일부 또는 전부가 다시 겹칠 수 있습니다.
- 전체 문서가 8개 미만이면 중복 없이 가능한 만큼 표시합니다. 일일 문서를 먼저 최대 4개 배정합니다.

검색어가 바뀌는 입력 이벤트마다 바로 아래의 관련도순 문서 후보를 최대 6개 갱신합니다. 한글 자음·모음을 조합하는 중에도 갱신하며, 이미 읽은 본문 색인을 즉시 사용합니다. 제목과 요약을 보고 클릭하거나 방향키로 선택한 뒤 Enter로 열 수 있습니다. Esc 또는 바깥 클릭으로 후보 목록을 닫습니다. Enter나 검색 버튼, ‘전체 검색 결과 보기’를 누르면 전체 결과로 이동합니다. 문서 읽기 화면의 검색창에서도 같은 방식으로 작동합니다.

새 검색의 기본 정렬은 관련도순입니다. 제목 완전일치, 제목 앞부분 일치, 제목 포함, 여러 검색어의 제목 일치를 우선하고 이후 태그·요약·본문을 봅니다. 같은 관련도는 제목순으로 정렬합니다. 한글 정규화와 대소문자, 띄어쓰기 차이를 반영하며 여러 검색어를 쓰면 모든 단어가 일치하는 문서를 찾습니다. 다른 정렬을 직접 선택해도 제목 완전일치 문서는 맨 위에 표시합니다. 제목·태그·요약 결과를 먼저 보여 주고 본문 검색이 끝나면 후보를 갱신합니다.

- 아무 문서 열기: 모든 문서 중 하나로 바로 이동합니다. 문서 읽기 중에는 현재 문서를 제외합니다(문서가 1개일 때는 제외하지 않음).
- 검색: 제목·태그·요약·본문을 검색하며 여러 단어는 모두 포함하는 문서를 찾습니다. 최초 검색 시 본문을 최대 4개씩 병렬로 불러와 메모리에 보관합니다. 읽지 못한 파일은 안내하고 다음 검색에 재시도합니다.
- 전체 목록은 ㄱㄴㄷ순 / 무작위 순 / 오늘의 무작위 순 / 최근 수정된 순을 지원하며, 검색 결과에는 관련도순이 추가됩니다. 최근 수정 정렬은 `db.js`의 `updatedAt`을 내림차순으로 비교합니다. 같은 날짜는 ㄱㄴㄷ순이며, 날짜가 없거나 잘못된 문서는 마지막에 둡니다. 실제 파일의 수정 시각을 자동으로 읽지는 않으므로 본문 수정 시 `updatedAt`도 갱신하세요. 뒤로 가기·앞으로 가기 지원.

- 단축키: `A`로 아무 문서를 엽니다. 읽는 중에도 다른 문서로 이동하며, 검색창·선택 상자·편집 영역의 입력과 조합키에는 반응하지 않습니다. `Esc`는 읽던 문서에서 직전 목록으로 돌아갑니다.
- 홈에서는 오늘의 문서를 우연한 발견 위에 표시합니다.
- 태그 필터 다음에 정렬 기준을 표시합니다. 필터는 `db.js`의 태그를 중복 없이 자동 수집해 ㄱㄴㄷ순으로 표시합니다. 태그는 정확히 일치하는 문서를 고르며 검색·정렬과 함께 적용됩니다. 선택 조건은 URL에 저장되어 뒤로 가기·새로고침에도 유지됩니다. 문서의 태그를 눌러 해당 목록을 열 수도 있습니다.

태그는 큰 분야 중심의 19개 분류로 관리하며 문서당 1~3개를 사용합니다. 인물명과 세부 이론명은 제목·본문 검색으로 찾습니다. 논증·추론·언어 분석 문서는 `논리학` 태그로 모아 볼 수 있습니다.

‘오늘의 무작위 순’은 한국 날짜를 시드로 전체 문서를 섞습니다. 같은 날짜와 같은 문서 목록에서는 새로고침·브라우저·등록 순서와 무관하게 동일하며, 검색과 태그 필터도 그 순서를 유지합니다. 날짜가 바뀌면 새로운 시드를 사용하고 열린 화면은 30초 간격 또는 탭 복귀 시 갱신합니다. 일반 ‘무작위 순’의 다시 섞기는 별도로 유지됩니다.

문서 읽기 화면 상단에서도 전체 문서의 제목·태그·본문을 검색할 수 있습니다. 검색어를 입력한 뒤 Enter나 검색 버튼을 누르면 결과 목록으로 이동합니다. 입력 중에는 검색창 아래에 후보 문서를 표시합니다.

## 날짜 기반 무작위 추출의 원리

1. 현재 시각을 `Asia/Seoul`로 해석해 `2026-11-02` 같은 날짜 키를 만듭니다.
2. `knowledge-daily:2026-11-02` 문자열을 FNV-1a 방식의 32비트 해시로 숫자 시드로 바꿉니다.
3. 시드를 Mulberry32 의사 난수 생성기에 넣습니다. 같은 시드는 항상 같은 난수 수열을 만듭니다.
4. 문서를 ID순으로 맞춘 뒤 이 난수 수열을 쓰는 Fisher–Yates 방식으로 섞고, 앞의 최대 4개를 선택합니다.
5. 선택된 ID를 전체 목록에서 제외하고, 남은 문서를 일반 `Math.random()`으로 섞어 최대 4개를 우연한 발견에 표시합니다.

따라서 같은 날짜와 같은 문서 목록에서는 브라우저나 새로고침 여부와 관계없이 오늘의 문서가 같습니다. 다음 날짜에는 시드가 달라집니다. 날짜 사이에는 일부 문서가 겹칠 수 있고, 무작위 추첨이므로 다른 날에도 같은 네 문서가 나올 가능성은 있습니다. 하루 내 두 묶음 사이에는 중복이 없습니다. 전체 문서 수가 8개라면 우연한 발견은 오늘의 문서를 제외한 네 문서이고, 새로 뽑을 때 순서만 달라집니다.
